# DoI V1 开发 Spec

**依据** [DoI 需求文档](./DoI需求文档.md) · [PWA 开发方案](./PWA开发方案.md)

DoI V1 是个人在 iPhone 上离线记录情侣共同经历的主屏幕网页 App。需求文档定义功能范围，本 Spec 定义实现、数据格式和验收。Apple 日历联动、双人同步和影像按后续版本单独设计。

## 1. 技术方案

使用原生 HTML、CSS 和 JavaScript ES 模块。页面、图表、图标和脚本随静态站点部署。记录和设置使用 IndexedDB，页面通过数据模块读写，表单和图表共用同一套日期及数值规则。

| 计划文件 | 职责 |
| --- | --- |
| `public/index.html`、`public/styles.css` | 页面骨架、底栏、表单和 iPhone 布局 |
| `public/app.js` | 导航、视图状态、表单及即时刷新 |
| `public/dates.js` | 本地日历日期、月份范围、星期和当前时段 |
| `public/db.js` | IndexedDB 初始化、查询、事务和迁移 |
| `public/stats.js` | 计算各项统计，供视图渲染 |
| `public/backup.js` | 备份编解码、文件选择、预览与恢复 |
| `public/manifest.webmanifest`、`public/icons/`、`public/sw.js` | 主屏幕安装和离线启动 |

页面用文本方式渲染昵称和备注，保留备注换行。站点托管只需静态 HTTPS，所有业务读写在设备本地完成。

## 2. 页面和交互

| 页面或入口 | 实现规则 |
| --- | --- |
| 月历 | 主屏幕启动后直接显示本月并选中今天。底栏顺序为「月历」「统计」「设置」，首页另有「历史记录」入口和「＋」按钮。月历从周日开始排列。有记录的日期始终只显示一个圆点。点日期后在下方列出当日所有记录，并可从当天列表补记。切到其他月份后点日期查看，点「今天」返回本月并选中当天。 |
| 新增／编辑 | 从首页「＋」进入时填今天，从当天列表进入时填所选日期。表单字段依次为日期、时段、时长、感受与备注。内容可滚动，底部固定「新建记录」或「保存修改」，适配安全区及键盘弹出。关闭表单返回来处。 |
| 历史记录 | 从月历页进入独立历史页，默认本月，可切换月份。按发生日期倒序，同日记录按创建时间倒序，ID 用于稳定排序。点击一条进入详情。 |
| 记录详情 | 展示日期、已填时段和时长、感受与备注，以及当前昵称。支持编辑和确认删除。修改后刷新详情，删除后回到来源列表。 |
| 统计 | 默认最近 365 天，支持指定月份。热力图保留固定范围，点日期跳到月历并选中对应日期。 |
| 设置 | 填写、修改或清空伴侣昵称，并提供 JSON 导出和恢复。昵称在详情按当前设置显示。 |

当天列表和历史列表都显示日期及已填写的时段、时长。空白项省略。「感受与备注」在详情打开后显示。空白月份、无记录日期和备份无新增记录时，显示对应的空状态。新增成功后回到月历并选中保存的日期，让补记结果可立即找到。

### 表单状态

- 新增时可选今天或过去的日期。今天的记录在打开表单时，根据 iPhone 本地时间自动选中时段。补记过去日期时初始留空。编辑已有记录时使用已保存的值。
- 时段只选一个，点另一项换选，再点当前项取消。草稿区分「自动选中」和「手动操作」。日期改为过去时清除自动预选，已手动选择的值保留。
- 时长的 10、20、30 分钟按钮填入同一个可编辑输入框。空值保存为 `null`。手填值使用正整数分钟。
- 日期和输入值校验通过后才开启保存事务。提交期间按钮防重复触发。写入完成后才提示成功、关闭表单和刷新页面。写入失败时保留草稿，显示简短错误并允许重试。

## 3. 数据契约

IndexedDB 名称为 `doi`，首次建库版本为 `1`。V1 建两个对象仓库，`records` 以 `id` 为键，并建立 `byDate` 跨日期查询索引。 `settings` 以 `key` 为键，`profile` 项保存 `partnerNickname` 字符串，空字符串表示未填写。

| `records` 字段 | 类型和约束 |
| --- | --- |
| `id` | UUID 字符串，在新建草稿时生成。编辑、导出、导入保持原 ID。 |
| `occurredOn` | `YYYY-MM-DD` 的实际公历日期，独立于时区。用户新建或改日期时须为今天或过去。 |
| `timeSlot` | `early_morning`、`morning`、`noon`、`afternoon`、`evening` 或 `null`。 |
| `durationMinutes` | 正整数或 `null`。 |
| `note` | 字符串，保留换行，空白内容保存为空字符串。 |
| `createdAt`、`updatedAt` | UTC ISO 8601 时间戳。新增时相同，编辑时保留创建时间并更新修改时间。 |

本地时段映射为凌晨 00:00–05:59、上午 06:00–10:59、中午 11:00–13:59、下午 14:00–17:59、晚上 18:00–23:59。按月查询以月初和下月月初作范围边界。展示、归月和分组使用 `occurredOn`。计算日期间隔用公历日期序号，避免夏令时和跨时区使日期偏移。

### 写入和迁移

- 数据模块提供按 ID 读取、按日期范围查询、新增、修改、删除、昵称设置、备份快照及批量合并。各写入在收到事务 `complete` 后回传成功。
- 新增使用 `add`，同一 ID 不覆盖。修改和删除在同一写事务中确认原记录仍存在。遇到已删除或修改期间已被另一窗口更新的记录，提示重新打开详情后处理。
- IndexedDB 版本升级由 `onupgradeneeded` 按旧版本逐步迁移。页面收到 `versionchange` 时释放旧连接并提示重开。升级被其他窗口阻塞时，提示关闭旧窗口。
- 数据库版本、静态缓存版本和备份格式版本分别管理。应用更新可以清理过期静态缓存。

事务细节参考 [W3C Indexed Database API](https://www.w3.org/TR/IndexedDB-3/)。

## 4. 统计规则

总览默认以设备今天为结束日期，向前含今天共 365 个日历日。切到历史月份时使用该月全部日期，本月使用月初到今天。范围内每天都计入周均分母。有记录的日期以 `occurredOn` 去重。

| 项目 | 计算和显示 |
| --- | --- |
| 总次数、有记录的天数、周均 | 总次数是记录数，有记录的天数是去重日期数。周均为记录数 × 7 ÷ 所选范围的日历天数，显示两位小数。 |
| 近一年热力图 | 固定按最近 365 天展示每天的记录数。按 0、1、2、3 次及以上区分颜色，并提供实际次数。点日期打开月历当天。 |
| 时长 | 只计算有时长的记录，显示样本数、平均分钟数及各区间次数。第一版区间为小于 15、15–24、25–34、35–44、45–54、55 分钟及以上。平均值显示一位小数。 |
| 连续记录 | 在所选范围内，去重并排序后计算最长连续有记录天数。范围内无记录时显示 0 天。 |
| 星期与时段 | 星期依据发生日期，时段用已保存的五种选项。留空的时段单列「未填写」，各项显示次数。 |

各区块标注自己的时间范围。零条记录时，总次数和周均显示零。时长或已填时段样本为零时提示暂无数据，时段仍可显示未填写数量。记录新增、修改、删除、恢复成功后，月历、历史和统计从最新数据重新计算。

## 5. JSON 备份和恢复

以下 JSON 使用虚构的记录演示备份格式。

**文件约定**　UTF-8 普通 JSON，文件名为 `DoI-backup-YYYY-MM-DD.json`。导出全部记录，备份范围以记录为单位，伴侣昵称属于设备设置。文件可直接读取。

```json
{
  "format": "doi-backup",
  "version": 1,
  "exportedAt": "2000-01-01T12:30:00.000Z",
  "records": [
    {
      "id": "00000000-0000-4000-8000-000000000001",
      "occurredOn": "2000-01-01",
      "timeSlot": "evening",
      "durationMinutes": 20,
      "note": "",
      "createdAt": "2000-01-01T12:29:00.000Z",
      "updatedAt": "2000-01-01T12:29:00.000Z"
    }
  ]
}
```

1. **导出**　使用只读事务取得完整快照。准备好文件后，通过用户点击触发系统保存流程。对支持文件分享的设备优先提供系统分享面板，允许保存到「文件」。另提供下载路径作为回退，由真机验证两者适用情况。 [W3C Web Share API](https://www.w3.org/TR/web-share/)
2. **校验与预览**　从系统文件选择器读取 JSON，校验格式标识、版本、所有记录字段和实际日历日期。备份恢复以文件里的日历日期为准，便于跨时区换机。任一记录校验失败时整份文件退出恢复流程。对合法文件按 ID 预览预计新增和跳过的条数，文件内同 ID 的重复项以首条为准。
3. **确认恢复**　开始一个读写事务，重新检查数据库中的记录 ID，只新增缺少的 ID，并以事务结果显示实际新增和跳过数。相同 ID 保留本机版本。任一写入失败则回滚本次导入。导入同一备份两次后，第二次新增为零。

## 6. 安装、离线和安全更新

- Manifest 使用固定应用标识，`start_url` 为站点首页，`display` 为 `standalone`。准备主屏幕图标并配置 Safari 的 `apple-touch-icon`。正式使用从 iPhone 主屏幕图标首次联网启动。
- Service Worker 安装时预缓存完整发布版本的 HTML、CSS、JS、Manifest 和图标。首批资源全部成功后才算安装成功。可安装且缓存就绪后，页面显示「可离线使用」。已激活版本从对应版本的缓存读取应用资源。站内导航回到已缓存的页面骨架。IndexedDB 负责全部记录。
- 更新发布时提交完整静态文件，并递增缓存版本。新 Worker 预缓存失败则保留当前可用版本。安装成功后等旧页面关闭再激活，避免编辑过程中强制刷新。激活时只清理 DoI 的旧版缓存。用户关闭并重开 App 后，继续使用原主屏幕图标与本机记录。 [W3C Service Workers](https://www.w3.org/TR/service-workers/)
- Windows 开发使用本地 HTTP 服务。真机验收用正式 HTTPS 地址，发布只上传 `public/` 并沿用同一生产网址。真机的「备份恢复测试」使用独立空环境和虚构数据。

## 7. 实施顺序和验收

1. **数据与日期**　完成模型、数据库读写与日期函数。验证同日多条、闰日、跨月补记、时段边界和错误写入。
2. **记录与回看**　完成月历、表单、历史、详情、昵称和删除确认。验证快速保存、补记、键盘弹出时可提交、重复点击只保存一次。
3. **统计与备份**　接入统计纯函数和文件备份。核对缺项、时间范围、重复导入、同 ID 内容不同、错误版本、事务失败和导入后的即时刷新。
4. **PWA 发布**　真机验证安装、飞行模式下冷启动及记录读写，验证备份保存到「文件」、从空环境恢复，以及同一网址升级后旧记录保留。

### 可复算的统计样例

固定今天为 2026-11-18，选 2026 年 11 月。准备 11 月 16 日「晚上、10 分钟」，17 日「时段和时长均空」和「下午、30 分钟」各一条，18 日「晚上、20 分钟」一条，另在 10 月 31 日录入任意一条。11 月预期为 **4 次、3 天、周均 1.56、平均时长 20.0 分钟（3 条）、最长连续 3 天**。时段为晚上 2 次、下午 1 次、未填写 1 次。年度热力图在 10 月 31 日和 11 月 17 日应分别显示 1 次和 2 次。
